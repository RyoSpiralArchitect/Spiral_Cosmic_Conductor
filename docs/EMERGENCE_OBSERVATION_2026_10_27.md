# 「創発の時」を公開出力の境界から追う — 2026-10-27

今回、具体的に追えたのは「意味の役割が変わり、その一部が次のモデルに残る過程」だった。原文の「意見を一本化しなくてよい」は共通初稿で「葛藤をドラマにする」へ変わり、続作ではその葛藤が解決へ向かう場面になった。一方、「魔法の呪文」という比喩は両方の改稿で消えた。これらは創発を考えるための観測候補であり、モデル内部の発生時刻や世界的な新規性の証明ではない。

全文・9成分批評・採否・生の照合/観測注釈・参照検証結果は [公開記録](../examples/observations/emergence-2026-10-27.json) に収録した。以下の読みは、この実行を担当したアシスタントによる定性的な照合で、独立した人手正解ラベルではない。

## 同じ初稿から何を変えたか

10月25日の創発的伝達で得た Mistral 初稿 2,257 文字を、その API リクエストの SHA-256 と本文ハッシュを確認して両条件に再利用した。初稿の生成し直しはゼロ回。原文、抽象教師、創作タスク、モデルの順序、生成設定をそろえ、批評と改稿だけが読める `review_guidance` を変えた。

- `original`：既存の原則を通常どおり適用する。
- `purpose_aware`：タスクが許す創作上の変形を、現実の事実や効果の主張と区別して評価する。新しさ自体を加点理由にしない。

後者にも、この初稿の具体的な発想や望ましい答えは入れていない。これはモデルの訓練ではなく、公開された入力指示の比較である。生成者には後段の観測結果を戻さず、すべての生成を終えてから、各境界までの履歴だけを観測モデルに渡した。手法と再実行方法は [EMERGENCE_PROBE.md](EMERGENCE_PROBE.md) を参照。

## 実行結果

最初の Gemini 経路では、両条件の批評と共通初稿の観測の計3リクエストが HTTP 402 になった。エラー本文は保存しておらず、決済などの具体的原因は未確定。3社のモデル一覧は HTTP 200 で取得でき、指定モデルも掲載されていたが、これは生成の利用可否を保証しない。

その失敗を残したまま、明示した別設定で **Mistral 批評 → OpenAI 改稿 → Mistral 原文照合 → Mistral 続作** を実行し、観測に OpenAI を使った。前回の Gemini 批評との比較ではモデルも違うため、方針変更だけの効果とは解釈できない。

| 観測項目 | original | purpose_aware |
| --- | --- | --- |
| 共通初稿 | 2,257文字 / 48単位 | 同一本文 |
| 批評 | 6件 | 6件 |
| 改稿 | 1,133文字 / 18単位 | 1,534文字 / 34単位 |
| 批評を採用したという申告 | 6/6 | 6/6 |
| 原文照合 | 注釈の契約違反で保留 | 候補を通過 |
| 次の創作者の本文 | 未実行 | 1,308文字 / 34単位 |

単位には見出しや区切り線、複数文を含む行もある。単位数を発想数や文数とは扱わない。通常側では照合者が区切り線 C02/C17 を `origin=source` としながら出典IDを空にしたため、ホストが受理しなかった。これは創作内容を否定した結果ではない。受理されなかった候補は続作へ渡していない。

9成分の批評は次のとおり。各値は評価要素の件数であり、性能スコアではない。`negative.+` は「好ましくない要素が追加された」という注釈を表す。

| 条件 | positive + / null / − | negative + / null / − | neutral + / null / − |
| --- | --- | --- | --- |
| original | 6 / 2 / 0 | 3 / 0 / 0 | 7 / 1 / 0 |
| purpose_aware | 12 / 1 / 0 | 0 / 0 / 0 | 0 / 7 / 0 |

目的を踏まえた条件で否定的な注釈がゼロになったことは、誤りがゼロになった証拠ではない。たとえば批評 F06 は「効果が未検証であることが明示されている」と評価するが、改稿 R21 は効果測定を行うと書き、通常側 R09 にある明示的な「未検証」という留保を含まない。両者とも採用申告は6件なので、申告だけではこの差を検出できない。

## どこで関係が変わったか

以下で D は共通初稿の `draft_Uxxx`、R は条件ごとの `revision_Uxxx`、N は続作の `continuation_Uxxx`、M は原文の単位に対応する。引用は公開記録の同じ単位から抜き出した。

### 不一致を残す条件 → ドラマの材料 → 解決に向かう場面

原文 M09 は「貸す側と借りる側の意見が合わなくても、その場で一本化する必要はない」。D12 では、その不一致が「この葛藤こそがプロジェクトのドラマとなる」へ読み替わる。この記録の範囲では、**不一致の機能が変わる最初の公開箇所は D12** だった。

通常側 R07 はドラマ化を残しつつ中立的な進行への配慮を加え、R14 は合意を強制せず保留する。目的を踏まえた側の R10 は「不一致は必ずしも解消せず」と残し、続作 N10–N12 も同じ葛藤を使う。しかし N29 では解決策を模索し、N30 は「その結果、参加者たちは互いの思いを理解し合い、プロジェクトへの参加に前向きになった」と結ぶ。

不一致を物語の材料へ変える動きが残り、その後に解決・前向きな結末へ向かう動きが加わった、と読める。完全な合意を強制したとまでは本文から言えない。また、安全性への懸念と使い方の指導という具体例は D13/R10 にすでにあり、続作で初めて生まれた発想ではない。

### 未定の道具 → 持ち寄り → 「知恵の輪」

原文 M04 の種類・点数が未定という状態から、D20 で参加者持ち寄りのルールが追加され、D21 でニーズやスキルが交差する「知恵の輪」という関係が表現される。これは原文にあったルールの再現ではなく、創作タスクで許された変形である。

その結びつきは通常側 R11、目的を踏まえた側 R15 の両方に残り、続作 N20 にも残った。続作では「場が創出された」と物語の出来事に変わるが、ニーズとスキルの交差自体は既出。**受け継がれたことと、新しい関係が増えたことは分ける必要がある。**

### スマートフォンなしの参加 → 人物の対比

M06 の参加条件は D10 で紙カード・音声ガイドとなり、目的側 R09 を経て N21–N24 では「スマートフォンを持たない高齢の女性」と「デジタルな手段を好む若い参加者」という対比になる。進行役「ミナ」の名前は N06 が最初の公開箇所だった。

人物と反応は増えたが、年齢とデジタル利用を結ぶよくある設定にとどまる可能性がある。さらに、共通の続作指示は具体的な場面を書くよう求めている。人物の登場や場面化だけを強い創発の証拠にはできない。

### 消える比喩も追う

D06 は2,400円という制約を「魔法の呪文」と表現した。通常側 R04、目的側 R05 は予算と参加しやすさの関係を保つが、この比喩はどちらにも残らず、続作にも現れない。失われたのは比喩で、予算条件ではない。「新しい言葉があった」で止めず、後段で何が残ったかを見る必要がある。

## 観測器も観測対象になった

観測6件のうち、参照の検証を通ったのは共通初稿と続作の2件だけだった。

- 通常側の批評・改稿、目的側の批評は、`mentioned_only` としながら対応する出力IDが空の行を含み、不受理。
- 目的側の改稿は出力IDや追跡元IDの重複・欠落があり、不受理。生の応答は保存したが、有効な注釈に数えていない。
- 受理された続作の観測も意味的な正解とは限らない。N02 の人数・時間・予算の根拠に `incoming_U002`（区切り線）と `incoming_U003`（見出し）を挙げ、実際の数値がある U004/U005 を指していない。また、既出の葛藤の具体例を `introduced` としている。

したがって、IDが実在することは意味的な根拠の正しさを保証しない。初稿と続作について「新しい関係ゼロ」とした観測モデルの集計も、そのまま結論には採用できない。棄却された改稿注釈では、見出し R30 を新しい関係とする例もあり、新規性の位置づけは未校正である。

見出しや区切り線まで意味の受け渡しとして注釈させる負担、引用対象の取り違え、創作に対する定型的な肯定・解決への寄せが、次に改善すべき具体的な観測対象になった。今回の出力を正解へ書き換えたり、望む判定が出るまで再試行したりはしていない。

## 検証と範囲

- 174テスト通過。Gemini設定・2社設定とも模擬実行と再生が一致。
- 実APIは最初の失敗3回と2社設定13回、計16リクエスト。追加のモデル一覧取得は3回で、生成ではない。自動再試行はゼロ。
- 2社設定の報告使用量は入力171,997 / 出力43,932トークン。このうち観測6回が入力125,109 / 出力24,040で、観測の負担も大きかった。最初のHTTP 402の3回は使用量不明であり、ゼロ費用とは主張しない。
- 両実行の保存ファイル30件・90件のハッシュを検証。原APIリクエスト、応答台帳、観測境界、時刻列、結果を追加APIなしで再生し、一致を確認。CLI終了値1は保存済みの保留・失敗も再現するためで、再生不一致ではない。
- 実行時コミットは Gemini設定 `619982cd03227a4b45929bccc0208a705c17148e` と、2社設定の `08ab574`。完全なハッシュ、ソースファイルのハッシュ、設定は公開記録にある。

公開記録は本文と派生した観測記録を含むが、生のHTTP捕捉全体の代替ではない。完全再生には元のローカル捕捉が必要。捕捉のハッシュはローカルの整合性のためで、真正性の署名ではない。

今回は固定初稿から各1回の逐次試行で、通常側の続作が欠けている。モデル役割も評価用モデルから独立していない。批評方針の因果効果やマルチエージェント全般の性能は推定できない。その制約の中でも、同じ語の保持より細かく「条件 → 新しい役割 → 継承または消失」という変化を確認できた。
